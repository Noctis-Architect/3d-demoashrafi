# درس‌ها: چیزهایی که کاربر رد کرده

هر ردیف یه شکایت واقعی کاربر تو سشن‌های قبلیه (۲۴ تا ۲۷ نوامبر ۲۰۲۶) و راهی که آخرش جواب داد. کاربر وقتی نتیجه شبیه عکس نیست خیلی تند می‌شه؛ این رو نشونهٔ استاندارد کیفیت بگیر و هر مورد رو قبل از اینکه خودش ببینه، خودت چک کن.

| شکایت کاربر (خلاصه) | علت | راه درست |
|---|---|---|
| «هر چی دمو ساختی پاک کن، اصلاً شبیه عکسشون نیست» | محصول‌ها از روی عکس با کد ساخته شده بودن | فرم فقط از GLB؛ کد فقط برای قطعه‌های متحرک |
| «من فایل سه‌بعدی دادم، گفتم مو به موی همون رو با کد اجرا کن، نه اینکه همون رو بذار و ادیت کن» | GLB مستقیم تو صفحه گذاشته شده بود | تبدیل به `assets/models/<id>.js` و ساخت در مرورگر |
| «با کد کامل همه‌شو طراحی کن… اگه نیاز بود از فایل بیاد» و بعد «این کد خیلی بد می‌زنه، اصلاً شبیهش نمی‌شه» | بدنهٔ چستر با کد ساخته شد و دسته‌ها شبیه لوله‌ی صاف شدن | بدنه از اسکن (صاف‌شده با Poisson)، فقط کوسن با کد. اگه کاربر کد خواست ولی نتیجه شبیه نشد، برگرد به اسکن و توضیح بده چرا |
| «نباید اینقد همه‌چی براق باشه» | clearcoat و specular زیاد | satin/matte پیش‌فرض |
| «شکستگی، پارگی، ناهمواری رو درست کن، ولی در حدی که به کنده‌کاری‌ها آسیب نزنه؛ چروک پارچه لازم نیست» | اسکن Tripo روی پارچه چروک و سوراخ داره | `poisson_unpillow` با صاف کردن جهت‌دار؛ کنده‌کاری‌ها دست نمی‌خورن |
| «بین چوب و پارچه چرا اینقدر پارگی هست؟» | پارچه دقیقاً روی مرز چوب بریده شده بود | پارچه پشت چوب ادامه پیدا کنه و کمی عقب بره (`--hem`، `--push`)، تا پشت درز همیشه پارچه باشه |
| «تغییر رنگ چوب و پارچه درست از هم جدا نشدن» | برچسب بر اساس رأس، و رنگ پارچه روی ریل نشت کرده بود | `seg2.py`: برچسب هر مثلث، محدودهٔ مجاز چوب، مرز روی شیار |
| «کلاف بشدت خرابه… از مدل GLB کلافشو بردار، این چیزی که هست آشغاله» | کلاف با Poisson دوباره ساخته شده بود | `frame_from_scan.py`: کلاف دقیقاً از GLB، فقط نیمهٔ چپ قرینه، برش صاف روی ریل |
| «دسته‌ها و تاجش اون خط چروکی که ظاهر مبل بود رو فید کردی، برگردون» | صاف کردن زیادی خط طراحی رو هم پاک کرد | `--crease`؛ فرق «چروک اسکن» و «خط طراحی» رو از عکس تشخیص بده |
| «تکسچر خیلی مخملی شده، شبیه عکس نیست» | velvet با sheen بالا | شنیل راه‌راه (`slub`) با sheen کم |
| «کفی مبل تیزه… کناره‌هاش اینقدر کرو نیست، کوسن‌هاش اینقدر گرد نیست، مربعی‌تره» | فرم تشک و کوسن از عکس خونده نشده بود | `--box` برای گوشهٔ تشک، `shape:'square'` برای کوسن |
| «این چه کوسن‌هاییه، مکعبی چرا شده؟» | اصلاح بیش از حد به سمت مربع | کوسن مربعی یعنی دور مربع با گوشهٔ نوک‌تیز و وسط پف‌دار که تا درز نازک می‌شه، نه جعبه |
| «کفی مبل از پشت جدا شدگیش معلوم نیست» | تشک به پشتی چسبیده بود | `--tuck` لبهٔ پشت تشک |
| «تو این نیمکت، تو فایل اصلی این شاخ وسط وجود نداره… بقیهٔ بخش‌ها دست نخوره، حتی تقارنش» | قرینه کردن نیمهٔ چپ یه نوک تیز ساخت | `flatten_crest.mjs`: فقط همون رأس‌ها |
| «پشت کار زیر کفی می‌خوام صاف باشه مثل عکس» | اسکن نوار پشت رو کنده‌کاری‌دار ساخته بود | `flatten_back_apron.mjs`: نوار صاف، نرمال تخت، بدون سایهٔ پخته |
| «زیر کشو و این‌ها با عکس فرق داره… رنگ تو کشوها و زیرش یکی باشه» | جزئیات دامنه و رنگ حفره | منحنی‌ها از GLB اندازه‌گیری، `SURF.cavity` همرنگ بدنه |
| «پشت کنسول چرا خمیدگی داره؟ پشتش باید صاف باشه» | موج اسکن روی لبهٔ پشت رویه | `TOP_BACK` ثابت؛ پشت مبلمان دیوارکوب صافه |
| «این جعبه چیه درست کردی که از کنار و پشت ریده تو ظاهر» | جعبهٔ کشو از بدنه بیرون زده بود | جعبه داخل کوچک‌ترین دهانه، هم‌منحنی رویه؛ و گزینهٔ «کشوی تزئینی» بدون جعبه |
| «این دو تا بخش هنوز یکم بیرون‌زدگیشون باید کم بشه» (سه بار) | برآمدگی اسکن بیشتر از عکس بود | ضریب روی همون بخش (`BULGE=0.7`)، دو سر و وسط ثابت |
| «کنارهای در وسط هم نباید کج باشه» | منحنی تا وسط ادامه داشت | `flatMid`: وسط کاملاً صاف، گذر نرم |
| «کوسن‌های ساحل خیلی کارتونیه و خیلی جاها می‌ره تو مبل» | کوسن بدون برخورد واقعی | `addSoftPillows` با میدان فاصله و تغییر شکل |
| «کوسن‌ها زاویه ثابته، ممکنه کسی کج بودن کوسن‌های کنار رو نخواد» | فقط یه چیدمان | گزینهٔ «کمی کج / صاف و مرتب» |
| «مبل ال بشدت کارتونیه» | جعبه‌های کدی صاف و بی‌حالت | چین ملایم، شکم، گودی نشستن، قیطان، سایهٔ تماس |
| «لگ داره… رو سیستم هم لگ داره» | مثلث‌های زیاد، MSAA روی هر فریم، raycast کند | `fastPick`، رندر بی‌MSAA موقع حرکت، وضوح پویا، `lite.mjs` روی بخش‌های صاف |
| «تا وقتی درست نشده و خروجی تمیز برای کارفرما درنیومده… ادامه بده» | کار نیمه‌کاره تحویل داده شد | چک‌لیست qa.md؛ تا همه رد نشده، ادامه |

## الگوهای کلی
- کاربر معمولاً با عکس صفحه (screenshot) و یه جملهٔ کوتاه می‌گه چی غلطه. بقیهٔ چیزهای خراب رو خودت پیدا کن؛ نذار دوبار بگه.
- وقتی می‌گه «فقط همین رو درست کن»، یعنی هیچ چیز دیگه‌ای تکون نخوره.
- «مثل عکس» از «مثل فایل» مهم‌تره، **به‌جز** کنده‌کاری‌ها که باید عین فایل باشن.
- اگه یه درخواست با قانون‌های طلایی تضاد داره (مثلاً «کل مبل رو با کد بساز»)، یه بار کوتاه تضاد رو بگو. اگه باز همون رو خواست، انجامش بده، ولی کنده‌کاری‌ها رو از فایل بیار.
